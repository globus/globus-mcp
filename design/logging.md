# Audit logging spec

The MCP server maintains a structured audit trail of all actions performed.

## LIMITATIONS
* Not all harnesses capture MCP invocation logs by default, and this may be inconsistent even within products for the same vendor. 
  * If audit trail is important, adjust your run command to ensure that stderr is captured, or use a tool like docker to ensure that logs are saved.
* The 2026 version of the MCP spec is stateless, and there is no consistently implemented way to identify the specific LLM conversation that invoked the tool. The `server_session_id` we provide is a synthetic value generated on MCP server startup, and has no relevance to the LLM session generated by your harness / chatbot. MCP headers such as `mcp-session-id` have been deprecated and are not implemented uniformly across all clients or transports.
* Tool calls rejected by argument validation (bad enum values, missing required fields, etc.) never reach our tool functions, so log support may be inconsistent

## General guidelines
1. Logs are written to stderr by default, due to the `stdio` transport requirement that `stdout` be reserved for tool output. 
2. This application uses structured logging (JSONL) to facilitate querying. 
3. Logs should identify tool calls, tool errors, and invocations of remote resources. Identity information (including globus user and agent session, where applicable) should be captured to faciliate auditing. 
   * A specific list of fields is provided within
   * Certain system errors do not reach tool calls,

## Schema

Every log line is a single JSON object. Fields fall into two groups: a base envelope
present on every line, and per-event fields layered on top.

### Base fields (every line)

| Field               | Type                                                    | Description                                                                                        |
|---------------------|---------------------------------------------------------|----------------------------------------------------------------------------------------------------|
| `timestamp`         | ISO 8601 UTC string                                     | When the event happened                                                                            |
| `level`             | `DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL`     | Standard Python logging severity.                                                                  |
| `event`             | short stable string, e.g. `"tool_call"`, `"tool_error"` | Names the kind of entry                                                                            |
| `message`           | human-readable string                                   | One-line summary, so the log is scannable without decoding event-specific fields                   |
| `request_id`        | string                                                  | The MCP JSON-RPC request id (`ctx.request_id`) - ties every line from one tool invocation together |
| `server_session_id` | UUID string                                             | A unique identifier per server process (not chatbot session ID)                                    |

### `tool_call` / `tool_error` fields (added on top of the base)

| Field             | Type                                  | Description                                                                                                  |
|-------------------|---------------------------------------|--------------------------------------------------------------------------------------------------------------|
| `tool_name`       | string                                | Which tool was called.                                                                                       |
| `service`         | string                                | Which namespace the tool belongs to- eg "compute", "transfer"                                                |
| `globus_identity` | UUID string, absent if not applicable | If a globus resource is invoked, specify the Globus identity used.                                           |
| `client_name`     | string or `null`                      | The connecting MCP client/harness's declared name (`clientInfo.name`). Not a unique conversation/ session ID |
| `client_version`  | string or `null`                      | The connecting MCP client/harness's declared version (`clientInfo.version`)                                  |

### `tool_error`-only fields

| Field           | Type   | Description              |
|-----------------|--------|--------------------------|
| `error_type`    | string | The exception class name |
| `error_message` | string | `str(error)`             |
